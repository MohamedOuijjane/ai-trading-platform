6. CLIENT DATA-FETCHING ARCHITECTURE (2026-04-14 Late — NEW)
================================================================================

SHARED STORES (src/store/):

marketStore.js — 30s TTL in-memory cache for /api/v1/market/prices/
  getMarketPrices(forceRefresh?: boolean): Promise<Record<string, number>>
  - Returns immediately from cache if TTL not expired
  - Logs: "[marketStore] Prices cache hit" vs "[marketStore] Fetching prices..."
  - Normalizes both array and object response formats
  - Falls back to empty {} on error
  clearPricesCache()

portfolioStore.js — 30s TTL in-memory cache for /api/v1/portfolio/
  getPortfolio(forceRefresh?: boolean): Promise<PortfolioData>
  - Returns immediately from cache if TTL not expired
  - Logs: "[portfolioStore] Portfolio cache hit" vs "[portfolioStore] Fetching..."
  - Falls back to { balance: 0, positions: [], pnl: 0 } on error
  clearPortfolioCache()

BEFORE (each page fetched independently, no cache, no guard):
  Dashboard  ──fetch──→ /api/v1/market/prices/   (fresh, every mount)
  Trade      ──fetch──→ /api/v1/market/prices/    (fresh, every mount)
  Portfolio  ──fetch──→ /api/v1/portfolio/       (fresh, every mount)
  Prediction ──fetch──→ /api/v1/predict/{ticker}/ (every render + on ticker change)

AFTER (centralized stores, 30s cache, cancelled guard):
  marketStore ──fetch──→ /api/v1/market/prices/   (cached 30s)
  portfolioStore ──fetch──→ /api/v1/portfolio/    (cached 30s)

  Dashboard  ──uses marketStore──→ cached prices
  Trade      ──uses both stores──→ cached prices + portfolio
  Portfolio  ──uses portfolioStore──→ cached portfolio
  Prediction ──user action only──→ /api/v1/predict/{ticker}/

  Every useEffect uses:
    - let cancelled = false
    - if (!cancelled) setState(...)
    - return () => { cancelled = true }

USAGE IN COMPONENTS:
  DashboardPage.js:
    useEffect(() => { getMarketPrices().then(...) }, [])
    useEffect(() => { getTickerPrediction(ticker) }, [ticker, getTickerPrediction])
    NOTE: prediction is fetched on ticker change (NOT on every render)

  PortfolioPage.js:
    useEffect(() => { getPortfolio().then(...) }, [])

  TradePage.js:
    useEffect(() => {
      loadPortfolio()   // independent async, no await
      loadPrices()      // independent async, no await
      loadSettings()    // independent async, no await
    }, [])

7. AUTHENTICATION PIPELINE
================================================================================

BACKEND JWT FLOW:
1. User submits username + password
2. POST /api/token/ → CustomTokenObtainPairView (config/serializers.py)
3. CustomTokenObtainPairSerializer.get_token() adds to payload:
   - username
   - is_staff
   - is_superuser
4. Returns { access, refresh }

Token payload AFTER FIX:
{
  "token_type": "access",
  "exp": ...,
  "iat": ...,
  "jti": ...,
  "user_id": 1,
  "username": "admin",        ← ADDED
  "is_staff": true,          ← ADDED (was missing before!)
  "is_superuser": true       ← ADDED (was missing before!)
}

FRONTEND LOGIN FLOW:
1. authApi.login(username, password) → POST /api/token/
2. Frontend decodes JWT payload (NO backend call needed):
   const payload = data.access.split(".")[1]
   const decoded = JSON.parse(atob(payload.replace(/-/g, "+").replace(/_/g, "/")))
   const isAdmin = !!decoded.is_staff || !!decoded.is_superuser
3. login(token, { is_staff: isAdmin, username }) stores:
   - localStorage.access_token = token
   - localStorage.is_staff = "true" | "false"
   - localStorage.username = username
4. Redirect:
   isAdmin=true  → /admin/dashboard
   isAdmin=false → /app/dashboard

⚠️  CRITICAL: 401 response handling does window.location.href="/login"
   This is a HARD PAGE RELOAD — all React state + in-memory caches are LOST.
   User must re-authenticate. All store caches are cleared on logout but
   NOT on 401 redirect (see KNOWN ISSUES).

11. KEY SERVICE FLOWS
================================================================================

A) ML PREDICTION + AUTO-TRADE FLOW:
User → GET /api/v1/predict/{TICKER}/
  → PredictionProxyView (permission=AllowAny ⚠️)
    → PredictionService.get_prediction()
      → GET http://localhost:8001/api/v1/predict/{TICKER} (ML Service, 5s timeout)
      → Prediction.objects.create() (DB write on EVERY call ⚠️)
    ← { ticker, signal, confidence, price, valid, latency_ms }
    → _maybe_auto_trade(request, prediction, result):
        IF settings.auto_trade == True
        AND signal != "HOLD"
        AND confidence >= settings.min_confidence
        AND BotConfig.is_active == True
        AND BotConfig.paper_trading == False
        AND BotConfig.max_trade_amount / price > 0
        THEN:
          TradeService.execute_trade(user, ticker, signal, qty)
          → Trade.objects.create()
          result["auto_executed"] = True
        ELSE:
          result["auto_trade_skipped"] = "<reason>"
  ← Response with { ticker, signal, confidence, price, auto_executed,
                    trade_id, auto_trade_skipped }

B) PORTFOLIO AGGREGATION (⚠️ PERFORMANCE ISSUE):
User → GET /api/v1/portfolio/
  → PortfolioService.get_user_portfolio(user)
    → Trade.objects.filter(user=user).order_by('executed_at')
    → initial_balance = BotConfig.max_trade_amount or 10000
    → For EACH symbol (sequential ⚠️):
        PredictionService.get_prediction(symbol)  ← 5s timeout EACH
        Calculates avg_entry_price, unrealized_pnl
    → Returns: { balance, pnl, positions[], history[] }
  ← { balance, pnl, positions, history }

C) MANUAL TRADE EXECUTION (TradePage — fully defensive):
User → POST /api/v1/trade/ { ticker, action, quantity }
  Pre-submit validation:
    BUY:  if quantity * price > balance        → "Insufficient balance"
    BUY:  if quantity * price > maxTradeAmount → "Exceeds system limit"
    SELL: if quantity > positionQty            → "Not enough asset to sell"
  Blocked API call if validation fails (button disabled)
  → TradeService.execute_trade(user, ticker, action, quantity)
    → PredictionService.get_prediction(ticker) (current price)
    → Validates balance, max_trade_amount
    → Trade.objects.create()
  ← Trade object returned

D) MARKET PRICES FLOW (⚠️ PERFORMANCE ISSUE):
User → GET /api/v1/market/prices/
  → MarketPricesView (permission=AllowAny)
    → Loops 8 symbols SEQUENTIALLY ⚠️:
        PredictionService.get_prediction(symbol)  ← up to 5s EACH = 40s worst case
    → If ML down: returns STATIC FALLBACK MOCK DATA (BTC=$70000, etc.)
  ← Array of { symbol, price, change, change_pct, high, low, volume }

12. AUTO-TRADE SYSTEM
================================================================================

Backend: PredictionProxyView._maybe_auto_trade()
  Checks (in order):
    1. SystemSettings.auto_trade == True
    2. signal != "HOLD"
    3. confidence >= SystemSettings.min_confidence (default 0.75)
    4. BotConfig.is_active == True for user
    5. BotConfig.paper_trading == False for user
  If all pass:
    quantity = BotConfig.max_trade_amount / prediction["price"]
    trade = TradeService.execute_trade(user, ticker, signal, qty)
    result["auto_executed"] = True
    result["trade_id"] = trade.id
  If any fail:
    result["auto_trade_skipped"] = "<reason>"

Frontend: DashboardPage.js (src/features/dashboard/)
  After prediction response:
    auto_executed=true  → Green banner "Trade Executed Automatically"
    auto_trade_skipped → Yellow banner + reason + manual execute button
    auto_trade_error   → Red banner with error message

13. KNOWN ISSUES (LAST UPDATED: 2026-04-14 Late)
================================================================================
🔴 CRITICAL (breaks system):
  1. POST /api/register/ does not exist — RegisterPage always 404s
  2. GET /api/v1/metrics/ does not exist — /app/metrics always fails
  3. GET /api/v1/backtest/{ticker}/ does not exist — backtesting fails
  4. PortfolioService calls PredictionService PER POSITION — up to 5 sequential
     ML calls per portfolio load (5 × 5s = 25s worst case when ML is slow)
  5. MarketPricesView calls PredictionService 8× SEQUENTIALLY — 40s worst case
     when ML service is down before returning static fallback
  6. PredictionService saves Prediction to DB on EVERY ML call — adds latency
  7. 401 response in apiClient: window.location.href="/login" — HARD PAGE RELOAD
     All in-memory caches (marketStore, portfolioStore) are lost. Component
     re-mounts from scratch. No way to restore session gracefully.

🟠 HIGH (wrong behavior):
  8. PredictionProxyView is AllowAny — anonymous users can trigger predictions
     Auto-trade is blocked by _maybe_auto_trade checks, but prediction itself
     is exposed. DDoS surface: 8× ML calls per market prices request.
  9. GET /api/v1/predictions/ returns ALL predictions — not filtered by user
     Client users can see all platform predictions.
 10. Refresh tokens do NOT include is_staff/is_superuser claims
     Only access tokens have custom claims. Full re-login required on expiry.
 11. Module-level caches (marketStore, portfolioStore) are NOT cleared on logout
     If user A logs in, browses, logs out, user B logs in — caches still hold
     user A's data. Must call clearPricesCache() + clearPortfolioCache() on
     logout or on login.
 12. Settings endpoint (/api/v1/settings/) returns 403 for non-superuser
     TradePage fetches this on load — if 403, settings falls back to Infinity
     (acceptable fallback, but 403 pollutes logs)

🟡 MEDIUM (architecture):
 13. Old frontend (src/App.js) is legacy dead code (was rewritten but unused)
 14. client.js api{} object unused by modern features
 15. is_staff stored as string "true"/"false" in localStorage (type confusion)
 16. In-flight request deduplication missing — if two components call
      getPortfolio() simultaneously before either resolves, both hit the API.
      No request deduplication at the store layer.

16. HOW TO RUN (LOCAL)
================================================================================
A) PREREQUISITES:
   - Python 3.10+, Node.js 18+, PostgreSQL 15, Redis

B) BACKEND:
   cd backend
   python -m venv venv
   venv\Scripts\activate
   pip install -r requirements.txt
   python manage.py makemigrations administration
   python manage.py migrate
   python manage.py runserver 0.0.0.0:8000

C) ML SERVICE (optional — falls back to static prices if down):
   cd ml_service
   python -m venv venv
   venv\Scripts\activate
   pip install -r requirements.txt
   uvicorn main:app --host 0.0.0.0 --port 8001

D) FRONTEND:
   cd frontend
   npm install
   npm start

E) CREATE TEST USERS:
   python manage.py shell -c "
   from django.contrib.auth.models import User
   User.objects.create_user(username='admin', password='password',
                            is_staff=True, is_superuser=True)
   User.objects.create_user(username='client1', password='123456',
                            is_staff=False, is_superuser=False)
   print('Users created')
   "
